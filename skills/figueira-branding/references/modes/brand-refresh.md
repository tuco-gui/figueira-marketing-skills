# Mode: brand-refresh

## When to use
The strategy is still valid — audience, value proposition and positioning haven't changed — but the visual/verbal expression has aged, become inconsistent across channels, or was never well executed.

## What changes in the default workflow
- Gate 3 (strategy) is a confirmation, not a rediscovery. Quickly validate that the foundations still hold; do not reopen positioning unless validation reveals they don't — in that case, stop and tell the user the real mode is `rebrand`.
- No formal equity audit, but still audit the identity **as lived** in production (Gate 0) before proposing changes — a refresh that ignores what's already live tends to "solve" problems that don't exist and ignore the ones that do.
- Visual territories (Gate 6) must be modernization variations, not reinventions — the test is: someone who knows the brand today recognizes the evolution, rather than mistaking it for a new brand.

## Risks specific to this mode
- Using "needs to modernize" as a sufficient diagnosis (forbidden in Gate 1 of `SKILL.md`) — always land on a concrete cause: inconsistency across channels, illegible typography in digital, a palette that doesn't work in dark mode, etc.
- Doing a disguised rebrand because it's faster to get approved — if the proposed change alters name/logo recognition to the point that the current audience wouldn't recognize the brand, that's a rebrand.
- A refresh that only touches the brand board and never gets tested on real touchpoints (Gate 9).

## Minimum deliverable (LEAN)
Diagnosis of current expression + targeted adjustments (typography, palette, grid) + validation on 2-3 real touchpoints.

## Standard deliverable (STANDARD)
Evolution territories (can be fewer than 3 if the incremental nature of the refresh justifies it — but still comparable side by side) + updated system + revised guidelines.
