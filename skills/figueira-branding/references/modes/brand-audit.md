# Mode: brand-audit

## When to use
Diagnosis before deciding whether the brand needs to change anything. This is the entry mode when the request is "do we need to touch the brand?" — it does not assume the answer is yes.

## What changes in the default workflow
- It's the only mode that can end in "don't change anything" or "change X, not Y" as a valid and complete deliverable in itself.
- Total focus on Gate 0: distinguishing **declared** identity (brand book, guidelines, approved decision) from **lived** identity (what's actually in production across touchpoints).
- Always produce a structured diagnosis, even if the final recommendation is "no change needed" or "brand-refresh, not rebrand."

## Diagnosis structure
1. **What's declared** — brand book, guidelines, previously approved decisions (with date/source).
2. **What's actually in production** — auditable touchpoints: site, social, sales materials, packaging, signage, whatever is accessible.
3. **Gaps between declared and lived** — where execution diverges from what's documented, and for how long.
4. **Assessment by dimension** — use `references/qa/scorecard.md` as a checklist, even outside the formal Gate 11, because it's the most complete diagnostic tool available.
5. **Recommendation** — one of: no change / brand-refresh / rebrand / identity-extension / evidence gap that blocks a recommendation.

## Risks specific to this mode
- Recommending a rebrand as the default answer because "there's always room to improve" — the bar is: is there a real, nameable brand problem, not just room for polish.
- Auditing only the brand board (declared identity) and ignoring real production.
- Inventing market/audience perception to justify the recommendation — without real research, classify it as `HYPOTHESIS` or `NO DATA`.

## Minimum deliverable
Structured diagnosis (above) + recommended mode/depth for the next step, if any.
Brand-audit does not move on to execution by itself — it decides whether and how another mode should start.
