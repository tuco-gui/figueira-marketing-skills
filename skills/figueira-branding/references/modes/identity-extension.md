# Mode: identity-extension

## When to use
A new line, product, sub-brand, program or unit inside an existing parent brand. The goal is coherence between the new offering and the parent system — not reinventing the whole brand.

## What changes in the default workflow
- Gate 0 must include reading the parent brand's identity and brand architecture — without that there's no way to assess coherence.
- Gate 3 (strategy) needs to answer: is this extension endorsed, an independent sub-brand, or a product line under the parent brand? The answer defines how much of the visual/verbal system is inherited vs. created.
- Visual territories (Gate 6) are variations of **how the extension relates to the parent brand**, not three disconnected directions — each territory still needs to be genuinely different, but within the coherence space already defined.
- Does not generate full brand guidelines from scratch (Gate 10) — generates an addendum/extension to the parent brand's guidelines.

## Brand-architecture questions to resolve before identity
- Does the new offering reinforce or dilute the parent brand if it fails?
- Is the extension's audience the same as the parent brand's, or a new segment?
- Is there a strategic reason for visual/verbal distance (e.g., a very different category, cross-reputation risk), or is proximity the main asset?

## Risks specific to this mode
- Treating the extension as `new-brand` and ignoring the parent brand — breaks brand architecture and confuses the market about the relationship between the offerings.
- Copying the parent brand's system without adaptation, resulting in an extension that doesn't differentiate enough to justify existing separately.
- Skipping the explicit architecture decision (endorsed/sub-brand/line) and letting the team figure it out organically after launch.

## Minimum deliverable
Brand architecture decision + 1-3 extension territories coherent with the parent brand + applications on the new offering's touchpoints + addendum to the existing guidelines.
