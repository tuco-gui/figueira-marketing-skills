# Context selection

Use context by necessity, not availability.

Include a context item only when at least one is true:
- it changes the requested output;
- it constrains implementation;
- it identifies a required file, repository, asset, API, environment or audience;
- it prevents a likely mistake;
- it defines an acceptance criterion;
- it provides an essential reference that the destination model cannot infer.

Exclude:
- organizational history unrelated to the task;
- manifestos or principles already enforced by persistent agent/project context;
- repeated facts;
- motivational framing;
- stale implementation details that are not relevant to the requested change.

When the destination already has persistent context such as `AGENTS.md`, `CLAUDE.md` or `GEMINI.md`, do not restate it unless the current request depends on a specific exception or override.
