# Design modality

Use for design canvases, prototypes, wireframes, mockups, presentations, one-pagers and similar editable visual artifacts.

A design prompt should normally identify only the fields that materially affect the artifact:
- artifact type;
- purpose/outcome;
- audience;
- content or information hierarchy;
- required sections/screens/slides;
- layout and responsive behavior when relevant;
- interaction/prototype behavior when relevant;
- visual direction;
- provided assets or references and their roles;
- existing design system/brand system when the destination can already access it;
- handoff/export target when important;
- acceptance criteria.

Do not prompt a design surface as though it were a text-to-image diffusion model. Avoid camera/lens language unless the artifact contains imagery that actually needs it.

If the destination already has a configured design system, do not restate the entire brand specification. Mention only exceptions, task-specific choices or constraints.
