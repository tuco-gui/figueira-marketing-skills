# Mode — Landing Page

## Job

Convert a specific audience into one measurable primary action: lead, meeting, purchase, application, sign-up, or another defined conversion.

## Principle

An LP is not a shrunk-down homepage. It is a decision narrative with one dominant action.

## Before designing

Define:
- traffic source and message match;
- awareness stage;
- offer;
- mechanism/differentiation;
- objections;
- real proof available;
- primary action;
- secondary action only if truly necessary.

## Recommended architecture

Do not use a fixed sequence as a template. Choose and order blocks according to the thesis. Consider:
- hero as the thesis;
- problem/cost of inaction;
- desired transformation/outcome;
- mechanism;
- demonstration;
- proof;
- offer;
- objections/FAQ;
- risk reduction;
- CTA.

## Design

- The first viewport should communicate offer + context + next action without depending on scroll.
- Use visual rhythm to separate argument, proof and action.
- The CTA should feel like a consequence of the narrative, not a mechanically repeated button.
- Do not make every block carry the same weight.
- Avoid "12 sections stacked in cards."
- Use real visual proof when available.

## CRO

Validate:
- clarity of the proposition within 5 seconds;
- form friction;
- ad-to-page coherence;
- primary CTA;
- required fields;
- trust microcopy;
- mobile-first for social traffic;
- load speed;
- conversion tracking.

## Truth

Do not invent numbers, clients, reviews, logos, testimonials, openings, deadlines, bonuses, or availability constraints.
