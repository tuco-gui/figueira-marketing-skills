# Mode — Web App

## Job

Let a person perform recurring or complex tasks with clarity, speed, confidence and low cognitive load.

## Start with workflows

Before screens, map:
- actor;
- job;
- input;
- sequence;
- decisions;
- output;
- error;
- permission;
- frequency.

## Architecture

Consider:
- global navigation;
- contextual navigation;
- dashboard only when it aggregates a decision;
- lists/tables;
- detail view;
- create/edit;
- search/filters;
- settings;
- notifications;
- empty/loading/error states;
- onboarding.

## Density

Productivity can require more density than marketing.
Do not turn an operational system into a promotional site with excessive whitespace.
Use hierarchy, alignment and grouping to handle dense information.

## Components

Define complete states:
- default;
- hover;
- focus;
- active;
- disabled;
- loading;
- success;
- warning;
- error;
- empty.

## Data

- tables must be readable and manipulable;
- numbers need units/context;
- dashboards should answer questions, not decorate;
- charts only when they improve understanding;
- do not invent data in an environment presented as real.

## Operational UX

- destructive actions require clarity and reversibility when possible;
- immediate feedback;
- shortcuts for frequent jobs;
- persisted filters when useful;
- errors explain how to fix them;
- permissions cannot depend solely on hiding a button on the frontend.

## Mobile

Do not force 1:1 equivalence when the desktop job is complex. Define what's essential on mobile and what needs adaptation.
