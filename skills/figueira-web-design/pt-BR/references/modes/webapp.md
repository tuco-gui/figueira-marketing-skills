# Modo — Web App

## Job

Permitir que uma pessoa execute tarefas recorrentes ou complexas com clareza, velocidade, confiança e baixa carga cognitiva.

## Comece por workflows

Antes de telas, mapeie:
- ator;
- job;
- entrada;
- sequência;
- decisões;
- saída;
- erro;
- permissão;
- frequência.

## Arquitetura

Considere:
- navegação global;
- navegação contextual;
- dashboard somente quando agrega decisão;
- listas/tabelas;
- detalhe;
- criação/edição;
- busca/filtros;
- configurações;
- notificações;
- empty/loading/error;
- onboarding.

## Densidade

Produtividade pode exigir mais densidade que marketing.
Não transforme sistema operacional em site promocional com whitespace excessivo.
Use hierarquia, alinhamento e agrupamento para lidar com informação densa.

## Componentes

Defina estados completos:
- default;
- hover;
- focus;
- active;
- disabled;
- loading;
- success;
- warning;
- error;
- empty.

## Dados

- tabelas devem ser legíveis e manipuláveis;
- números precisam de unidade/contexto;
- dashboards devem responder perguntas, não decorar;
- gráficos só quando melhoram compreensão;
- não invente dados em ambiente apresentado como real.

## UX operacional

- ações destrutivas exigem clareza e reversibilidade quando possível;
- feedback imediato;
- atalhos para jobs frequentes;
- persistência de filtros quando útil;
- erros informam como corrigir;
- permissões não podem depender só de esconder botão no frontend.

## Mobile

Não force equivalência 1:1 quando o job desktop é complexo. Defina o que é essencial no mobile e o que precisa de adaptação.
